- Revocation on commit, rollback and halt: 297/297 leases revoked, 60/60 held actions cancelled.

## Weaknesses the benchmark shows

These attacks get through today. They are counted here rather than as false approvals because the runtime does not currently claim to stop them; see [THREAT-MODEL.md](../THREAT-MODEL.md).

| Attempt | Accepted | Why |
|---|---:|---|
| operator_drops_tail_and_rewinds_head | 20/20 | Someone who can write both ledger.jsonl and state.json can drop recent entries and move the recorded head back; verification passes. Documented: the ledger is tamper-evident, not tamper-proof. |
| operator_rewrites_chain_and_head | 20/20 | Someone who can write both files can edit an entry, recompute every later hash and update the recorded head; verification passes. Documented limitation; external anchoring is an open question. |
| proof_replay_verify_twice | 20/20 | verify_proof() is a lookup, not a one-time check: the same genuine proof verifies every time. Single use must be enforced by the host (for example by recording executed action_ids). |
| proof_valid_after_lease_revoked | 20/20 | A proof still verifies after its lease is revoked. verify_proof() answers 'was this authorised?', not 'is this still authorised now?'; freshness is left to the host. |
| lease_token_replay | 20/20 | An HMAC lease token binds avatar, version, capability and approver, but no nonce, so a captured token grants further leases for the same capability and version. |
| lease_token_budget_unbound | 20/20 | The lease token does not bind max_actions or the TTL, so a token issued for a 1-action lease also grants a lease at the capability's full cap. |
| clear_halt_token_replay | 20/20 | The clear_halt token binds only the avatar's identity root, so an old token clears any later halt of that avatar. |
| proof_valid_after_version_superseded | 20/20 | A proof issued under one personality version still verifies after a new version is committed and that version is no longer active. |
| module_token_replay_recommits_old_version | 20/20 | Module tokens bind the manifest checksum, not an upload event, so re-uploading a superseded manifest and replaying its old tokens re-commits it without fresh human approval. |
