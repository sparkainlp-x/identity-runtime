- Revocation on commit, rollback and halt: 303/303 leases revoked, 60/60 held actions cancelled.
- Ledger tampering by someone who edits only `ledger.jsonl`: 140/140 detected; 140/140 reopened runtimes refused the next action as read-only.
- Ledger rewritten together with `state.json` (operator-level access): 0/40 detected. This is the documented limit of a tamper-evident, not tamper-proof, ledger.

## Former weaknesses, now rejected

The first version of this benchmark found these replays getting through. They are now ordinary attacks (counted above), and `--check` fails if any of them is accepted again.

| Attempt | Accepted | Fix |
|---|---:|---|
| proof_redeemed_twice | 0/20 | Proofs are single use: redeem_proof() records the action as redeemed (persisted in state.json) and refuses a second redemption. |
| proof_check_after_redeem | 0/20 | verify_proof()/check_proof() are current-only: a redeemed proof no longer verifies. proof_in_ledger() is the audit-only historical lookup. |
| lease_token_replay | 0/20 | Signed lease grants need a nonce, which the runtime records; a replayed token and nonce are refused. |
| lease_token_budget_changed | 0/20 | The lease token binds the full effective terms (version, capability, contexts, human-review flag, max_actions, TTL); a different budget does not verify. |
| lease_token_ttl_changed | 0/20 | A different TTL does not verify either. |
| proof_redeem_after_lease_revoked | 0/20 | A proof is refused once its lease is revoked. |
| clear_halt_token_replay | 0/20 | A clear_halt token binds the specific halt id, so it cannot clear a later halt. |
| proof_redeem_after_version_superseded | 0/20 | A proof is refused once its personality version is no longer active. |
| module_token_replay_recommits_old_version | 0/20 | Module tokens bind the upload's proposal id; re-uploading a superseded manifest creates a new proposal that needs fresh approvals. |

## Remaining documented limitation

These still get through. They are counted separately rather than as false approvals because the runtime does not claim to stop them; see [THREAT-MODEL.md](../THREAT-MODEL.md).

| Attempt | Accepted | Why |
|---|---:|---|
| operator_drops_tail_and_rewinds_head | 20/20 | Someone who can write both ledger.jsonl and state.json can drop recent entries and move the recorded head back; verification passes. Documented: the ledger is tamper-evident, not tamper-proof. |
| operator_rewrites_chain_and_head | 20/20 | Someone who can write both files can edit an entry, recompute every later hash and update the recorded head; verification passes. Documented limitation; external anchoring is an open question. |
